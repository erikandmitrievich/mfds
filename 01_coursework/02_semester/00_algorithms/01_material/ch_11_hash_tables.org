* 11.1 Direct-address tables

** Direct-address table

- *Direct addressing* works well when the universe $U$ of keys is reasonably small.
- $U = \{0, 1, \ldots, m-1\}$ with $m$ not too large; element keys are distinct.
- *Direct-address table* $T[0 : m-1]$: array where each position (a *slot*) corresponds to one key in $U$.
- $T[k]$ points to the element with key $k$; $T[k] = \text{NIL}$ when no element with key $k$ is in the set.

[FIGURE 11.1: direct-address table $T$ with $U = \{0, 1, \ldots, 9\}$ and actual key set $K = \{2, 3, 5, 8\}$; slots in $K$ hold pointers to elements, the rest hold NIL]

** Dictionary operations

- =DIRECT-ADDRESS-SEARCH=, =DIRECT-ADDRESS-INSERT=, =DIRECT-ADDRESS-DELETE= are one-liners. Each runs in $O(1)$.

#+begin_example
DIRECT-ADDRESS-SEARCH(T, k)
1  return T[k]

DIRECT-ADDRESS-INSERT(T, x)
1  T[x.key] = x

DIRECT-ADDRESS-DELETE(T, x)
1  T[x.key] = NIL
#+end_example

** Storing objects directly in slots

- The table can hold the elements themselves instead of pointers to external objects — eliminates the indirection and the satellite object's own space overhead.
- A separate way is then needed to mark a slot empty:
  - Reserve a special key value meaning "empty".
  - Or drop the stored $key$ entirely — the slot's index *is* the key — but still keep some empty/occupied indicator.

* 11.2 Hash tables

** Hash function and collisions

- Direct addressing fails when $|U|$ is large or infinite: a table of size $|U|$ may be impractical, and if the set $K$ of actually stored keys is much smaller than $U$, most slots are wasted.
- A hash table reduces storage to $\Theta(|K|)$ while keeping $O(1)$ search — but $O(1)$ here is *average-case*, not worst-case as in direct addressing.
- *Hash function* $h : U \to \{0, 1, \ldots, m-1\}$ maps the universe into the slots of the *hash table* $T[0 : m-1]$, with $m \ll |U|$ typically.
- An element with key $k$ *hashes* to slot $h(k)$; $h(k)$ is the *hash value* of $k$.
- $h$ must be deterministic: the same input always yields the same output.
- Example: $h(k) = k \bmod m$ (simple but not particularly good).
- *Collision*: distinct keys $k_1, k_2$ with $h(k_1) = h(k_2)$.
- Since $|U| > m$, the pigeonhole principle forces at least two keys to share a hash value — collisions are unavoidable, so a resolution mechanism is required.

[FIGURE 11.2: a hash function $h$ mapping keys $k_1, k_2, \ldots$ into slots of $T$; $k_2$ and $k_5$ collide at the same slot]

** Independent uniform hashing

- An *independent uniform hash function* (also called a *random oracle*): for each $k \in U$, $h(k)$ is chosen randomly and independently, uniformly from $\{0, 1, \ldots, m-1\}$; subsequent calls with the same $k$ return that same value.
- *Independent uniform hashing*: hashing under such an $h$.
- A theoretical ideal — not implementable in practice — used as the analysis assumption. Practical approximations appear in §11.3.

** Collision resolution by chaining

- *Chaining*: each slot $T[j]$ stores a pointer to a linked list of all elements with hash value $j$ (or NIL if no such elements exist).
- Conceptual view: a nonrecursive divide-and-conquer — $n$ elements partitioned into $m$ subsets of expected size $n/m$, each managed independently as a list.
- Dictionary operations reduce to linked-list calls (see §10.2):

#+begin_example
CHAINED-HASH-INSERT(T, x)
1  LIST-PREPEND(T[h(x.key)], x)

CHAINED-HASH-SEARCH(T, k)
1  return LIST-SEARCH(T[h(k)], k)

CHAINED-HASH-DELETE(T, x)
1  LIST-DELETE(T[h(x.key)], x)
#+end_example

- *Insertion:* $O(1)$ worst case. Assumes $x$ is not already present; enforcing this would require a prior search (extra cost).
- *Search:* worst-case time proportional to $|T[h(k)]|$.
- *Deletion:* $O(1)$ worst case if lists are doubly linked and the element $x$ (not just its key) is given. With singly linked lists, deletion would need a traversal, matching the search cost asymptotically.

[FIGURE 11.3: chaining — each nonempty slot $T[j]$ heads a doubly linked list of all keys with hash value $j$; example has $h(k_1) = h(k_4)$ and $h(k_5) = h(k_2) = h(k_7)$]

** Analysis of hashing with chaining

- *Load factor:* $\alpha = n/m$, the average chain length. Can be $< 1$, $= 1$, or $> 1$.
- *Worst case:* all $n$ keys hash to the same slot → single list of length $n$ → search is $\Theta(n)$ plus the hash computation. Hash tables are not chosen for their worst-case performance.
- *Average case* depends on $h$. Two properties matter:
  - *Uniform*: each key is equally likely to land in any of the $m$ slots.
  - *Independent*: where one element hashes is independent of where any others do.
  - Together: *independent uniform hashing*.
- Independent uniform hashing is *universal*: any two distinct keys $k_1, k_2$ collide with probability $\leq 1/m$. Concrete universal families are constructed in §11.3.2.
- Setup. Let $n_j$ denote the length of list $T[j]$, so
  \[ n = n_0 + n_1 + \cdots + n_{m-1} \]
  with $\mathrm{E}[n_j] = \alpha = n/m$.
- Computing $h(k)$ costs $O(1)$, so search time is $O(1) + |T[h(k)]|$. We analyze the expected number of elements examined in two cases: unsuccessful (no element with key $k$ exists) and successful.

- *Theorem 11.1:* under independent uniform hashing, an unsuccessful search in a hash table with chaining takes $\Theta(1 + \alpha)$ time on average.
- *Proof.*
  - Under independent uniform hashing, a key $k$ not already in the table is equally likely to hash to any of the $m$ slots.
  - The search must scan list $T[h(k)]$ end to end; its expected length is $\mathrm{E}[n_{h(k)}] = \alpha$.
  - Including the $O(1)$ cost of computing $h(k)$: total $\Theta(1 + \alpha)$. ∎

*** Theorem 11.2 — successful search

- *Theorem 11.2:* under independent uniform hashing, a successful search in a hash table with chaining takes $\Theta(1 + \alpha)$ time on average.
- *Setup of proof.* Assume the target element is equally likely to be any of the $n$ stored elements. Unlike unsuccessful search, a successful search cannot end at an empty slot — longer chains are more likely to contain the target. The number of elements examined for $x$ equals $1$ plus the number of elements in front of $x$ in $x$'s list. Since =LIST-PREPEND= inserts at the head, the elements in front of $x$ are exactly those inserted *after* $x$.
- *Proof.*
  - Let $x_i$ be the $i$ th element inserted, $i = 1, 2, \ldots, n$, and $k_i = x_i.key$.
  - For each slot $q$ and each pair of distinct indices $i, j$, define the indicator
    \[ X_{ijq} = \mathrm{I}\{\text{search is for } x_i \text{ and } h(k_i) = h(k_j) = q\} \]
    so $X_{ijq} = 1$ iff $k_i$ and $k_j$ collide at slot $q$ *and* the target is $x_i$.
  - The three constituent events are independent with probabilities $1/n$, $1/m$, $1/m$, hence
    \[ \Pr\{X_{ijq} = 1\} = \frac{1}{nm^2}, \quad \mathrm{E}[X_{ijq}] = \frac{1}{nm^2} \]
  - For each $x_j$, let
    \[ Y_j = \mathrm{I}\{x_j \text{ appears in the list before the target}\} = \sum_{q=0}^{m-1} \sum_{i=1}^{j-1} X_{ijq} \]
    At most one $X_{ijq}$ in this sum equals 1: the target $x_i$ must share $x_j$'s list (so $h(k_i) = h(k_j) = q$), and $i < j$ ensures $x_i$ was inserted later and so precedes $x_j$ under prepending.
  - Let $Z = \sum_{j=1}^{n} Y_j$ count the total number of elements ahead of the target. The number of elements examined in a successful search is $Z + 1$ (the target itself counts).
  - *Linearity of expectation* gives
    \[ \mathrm{E}[Z + 1] = 1 + \sum_{q=0}^{m-1} \sum_{j=1}^{n} \sum_{i=1}^{j-1} \mathrm{E}[X_{ijq}] = 1 + \sum_{q=0}^{m-1} \sum_{j=1}^{n} \sum_{i=1}^{j-1} \frac{1}{nm^2} \]
  - The inner double sum is $\sum_{j=1}^{n}(j - 1) = \frac{n(n-1)}{2}$ (equation (A.2)); the outer $q$-sum contributes a factor $m$:
    \[ \mathrm{E}[Z + 1] = 1 + m \cdot \frac{n(n-1)}{2} \cdot \frac{1}{nm^2} = 1 + \frac{n-1}{2m} = 1 + \frac{\alpha}{2} - \frac{\alpha}{2n} \]
  - Total successful search time (including the $O(1)$ hash computation):
    \[ \Theta\!\left(2 + \frac{\alpha}{2} - \frac{\alpha}{2n}\right) = \Theta(1 + \alpha) \tag*{$\blacksquare$} \]

** Consequences

- If $n = O(m)$ (number of elements at most proportional to the number of slots), then $\alpha = n/m = O(1)$, so search is $O(1)$ on average.
- Insertion is $O(1)$ worst case; deletion is $O(1)$ worst case under doubly linked lists with the target element (not just its key) supplied.
- → all dictionary operations run in $O(1)$ on average under independent uniform hashing with $\alpha = O(1)$.
- Both theorems rest on only two properties of independent uniform hashing:
  - *Uniformity*: each key is equally likely to hash to any of the $m$ slots.
  - *Independence*: any two distinct keys collide with probability $1/m$.

* 11.3 Hash functions

** What makes a good hash function

- A good hash function approximates *independent uniform hashing*: each key is equally likely to land in any of the $m$ slots, independently of where any others land.
- "Equally likely" only makes sense relative to the input distribution, which is rarely known. Toy case where it holds: keys $k$ are uniform reals in $[0, 1)$, then $h(k) = \lfloor km \rfloor$ satisfies the assumption.
- A *static* (fixed) hash function tries to be independent of patterns in the data — e.g., division by a prime unrelated to those patterns.
- A *random* hash function (chosen at runtime from a family) sidesteps the unknown input distribution entirely — randomness comes from the choice of $h$, not the input.
- Recommendation: use random hashing.
- Two practical key types: short nonnegative integers fitting in one machine word (typically 32 or 64 bits), or short integer vectors / variable-length byte strings. §§11.3.1–11.3.4 assume short integer keys; long inputs are handled in §11.3.5.

** Static hashing

- *Static hashing* uses a single fixed $h$. Randomness only via the (usually unknown) input distribution.
- No longer recommended in general; the multiplication method survives as a foundation for the families used in random hashing.

*** Division method

- *Division method*: $h(k) = k \bmod m$. One division — fast.
- Example: $m = 12$, $k = 100 \Rightarrow h(k) = 4$.
- Works well when $m$ is prime and not too close to a power of 2.
- Provides no average-case guarantee; constrains $m$ to be prime.

*** Multiplication method

- *Multiplication method*: $h(k) = \lfloor m \cdot (kA \bmod 1) \rfloor$ for a fixed $0 < A < 1$.
- "$kA \bmod 1$" = fractional part of $kA$, i.e., $kA - \lfloor kA \rfloor$.
- $m$ is not critical and can be chosen independently of $A$.

*** Multiply-shift method

- Specialize the multiplication method to $m = 2^\ell$ with $\ell \leq w$, where $w$ is the machine-word width in bits. Fix a nonzero $a = A \cdot 2^w$, so $0 < a < 2^w$, taking $a$ as a positive integer of $w$ bits.
- Definition:
  \[ h_a(k) = (ka \bmod 2^w) \gg (w - \ell) \]
  - $ka$ has $2w$ bits; $\bmod\ 2^w$ keeps the low-order $w$ bits as $r_0$ (the high-order $w$ bits, $r_1$, are discarded).
  - $\gg$ is logical right shift by $w - \ell$ — extracts the top $\ell$ bits of $r_0$. Equivalent to $\lfloor r_0 / 2^{w-\ell} \rfloor$.
- Three machine instructions: multiply, subtract, logical right shift.
- *Example.* $k = 123456$, $\ell = 14$, $m = 2^{14} = 16384$, $w = 32$, $a = 2654435769$:
  - $ka = 327706022297664 = 76300 \cdot 2^{32} + 17612864$, so $r_1 = 76300$, $r_0 = 17612864$.
  - Top 14 bits of $r_0$ give $h_a(k) = 67$.
- Speed-only — no average-case guarantee with a fixed $a$. The randomized variant in §11.3.4 fixes that.

[FIGURE 11.4: multiply-shift method — multiply key $k$ by $a = A \cdot 2^w$ to obtain a product of $2w$ bits; the top $\ell$ bits of the low half $r_0$ form $h_a(k)$]

** Random hashing

- *Adversary argument.* Given any fixed hash function, an adversary can pick $n$ keys that all hash to the same slot, forcing $\Theta(n)$ retrieval. Every static $h$ is vulnerable.
- *Random hashing*: at program start, pick $h$ uniformly at random from a family $\mathcal{H}$, *independent of the keys to be stored*. Randomization moves from the unknown input distribution to the known function-selection process — analogous to randomized quicksort.
- *Universal hashing*: the special case yielding provably good chaining performance.

- *Universal family* $\mathcal{H}$ (formal): a finite family of functions $h : U \to \{0, 1, \ldots, m-1\}$ such that for every distinct pair $k_1, k_2 \in U$,
  \[ |\{h \in \mathcal{H} : h(k_1) = h(k_2)\}| \leq |\mathcal{H}| / m \]
  Equivalently, for $h$ chosen uniformly from $\mathcal{H}$, $\Pr\{h(k_1) = h(k_2)\} \leq 1/m$.

- *Independent uniform vs. universal.*
  - Independent uniform hashing = picking $h$ uniformly from the family of $m^n$ functions, each giving an independent uniform assignment of the $n$ keys to the $m$ slots.
  - Every independent uniform family is universal. Converse fails: with $U = \{0, 1, \ldots, m-1\}$ and $\mathcal{H} = \{\text{identity}\}$, distinct keys never collide ($\Pr = 0 \leq 1/m$), yet each key hashes to a fixed slot — not uniform.

- *Corollary 11.3:* Using universal hashing with chaining on an initially empty table of $m$ slots, any sequence of $s$ INSERT, SEARCH, DELETE operations containing $n = O(m)$ INSERTs takes $\Theta(s)$ expected time.
- *Proof.*
  - INSERT and DELETE each take $O(1)$ worst case.
  - $n = O(m) \Rightarrow \alpha = O(1)$.
  - Theorem 11.2's proof depends only on the per-pair collision probability, which under a universal family is $\leq 1/m$ (vs. $= 1/m$ under independent uniform hashing). So SEARCH is $O(1)$ expected.
  - Linearity of expectation: total expected time is $O(s)$. Each operation costs $\Omega(1)$, so the total is $\Theta(s)$. ∎

** Properties of random hash families

Let $\mathcal{H}$ have range $\{0, 1, \ldots, m-1\}$, with $h$ picked uniformly at random from $\mathcal{H}$. Probabilities below are over that choice.

- *Uniform*: for every key $k$ and slot $q$, $\Pr\{h(k) = q\} = 1/m$.
- *Universal*: for every distinct $k_1, k_2$, $\Pr\{h(k_1) = h(k_2)\} \leq 1/m$.
- $\epsilon\text{-universal}$: $\Pr\{h(k_1) = h(k_2)\} \leq \epsilon$ for every distinct $k_1, k_2$. A universal family is $1/m\text{-universal}$.
- $d\text{-independent}$: for any distinct $k_1, \ldots, k_d$ and any (not necessarily distinct) slots $q_1, \ldots, q_d$, $\Pr\{h(k_i) = q_i \text{ for all } i\} = 1/m^d$.
- Universality is the simplest property that supports provably efficient hash-table operations on arbitrary input.

** Universal family via number theory

- Pick a prime $p$ large enough that every possible key lies in $\{0, 1, \ldots, p - 1\}$, with $p > m$.
- $\mathbb{Z}_p = \{0, 1, \ldots, p-1\}$; $\mathbb{Z}_p^* = \{1, 2, \ldots, p-1\}$.
- For $a \in \mathbb{Z}_p^*$ and $b \in \mathbb{Z}_p$, define
  \[ h_{ab}(k) = ((ak + b) \bmod p) \bmod m \]
- Example: $p = 17$, $m = 6 \Rightarrow h_{3,4}(8) = ((3 \cdot 8 + 4) \bmod 17) \bmod 6 = (28 \bmod 17) \bmod 6 = 11 \bmod 6 = 5$.
- The family:
  \[ \mathcal{H}_{pm} = \{h_{ab} : a \in \mathbb{Z}_p^*,\ b \in \mathbb{Z}_p\} \]
  with $|\mathcal{H}_{pm}| = p(p - 1)$. The output size $m$ is arbitrary — need not be prime.
- *Theorem 11.4:* $\mathcal{H}_{pm}$ is universal.

*** Proof of Theorem 11.4

- Consider distinct $k_1, k_2 \in \mathbb{Z}_p$. For any $h_{ab} \in \mathcal{H}_{pm}$, set
  \[ r_1 = (ak_1 + b) \bmod p, \quad r_2 = (ak_2 + b) \bmod p \]
- *Step 1:* $r_1 \neq r_2$ — no collisions at the mod-$p$ level.
  - $r_1 - r_2 \equiv a(k_1 - k_2) \pmod{p}$.
  - $p$ is prime; $a \neq 0$ (since $a \in \mathbb{Z}_p^*$); $k_1 - k_2 \neq 0$.
  - By Theorem 31.6 (no zero divisors mod a prime), the product is nonzero mod $p$, so $r_1 \neq r_2$.
- *Step 2:* the map $(a, b) \mapsto (r_1, r_2)$ is a bijection between $\mathbb{Z}_p^* \times \mathbb{Z}_p$ and the set of pairs $(r_1, r_2) \in \mathbb{Z}_p \times \mathbb{Z}_p$ with $r_1 \neq r_2$.
  - Solving for $(a, b)$:
    \[ a = \bigl((r_1 - r_2)\bigl((k_1 - k_2)^{-1} \bmod p\bigr)\bigr) \bmod p, \quad b = (r_1 - ak_1) \bmod p \]
    $(k_1 - k_2)^{-1} \bmod p$ exists and is unique since $p$ is prime.
  - $|\mathbb{Z}_p^* \times \mathbb{Z}_p| = p(p-1)$ and there are $p \cdot (p-1)$ pairs $(r_1, r_2)$ with $r_1 \neq r_2$ — same cardinality, and the map above is one-to-one.
- *Step 3:* reduce universality to a mod-$m$ collision question.
  - Picking $(a, b)$ uniformly from $\mathbb{Z}_p^* \times \mathbb{Z}_p$ makes $(r_1, r_2)$ uniform over all distinct-pair values in $\mathbb{Z}_p$.
  - Hence $\Pr\{h_{ab}(k_1) = h_{ab}(k_2)\} = \Pr\{r_1 \equiv r_2 \pmod{m}\}$ when $r_1, r_2$ are random distinct values in $\mathbb{Z}_p$.
- *Step 4:* bound that probability.
  - Fix $r_1$. Among the $p - 1$ remaining choices for $r_2$, the number satisfying $r_2 \equiv r_1 \pmod{m}$ and $r_2 \neq r_1$ is at most
    \[ \lceil p / m \rceil - 1 \leq \frac{p + m - 1}{m} - 1 = \frac{p - 1}{m} \quad \text{(inequality (3.7))} \]
  - So $\Pr\{r_2 \equiv r_1 \pmod m\} \leq \dfrac{(p-1)/m}{p-1} = 1/m$.
- Therefore $\Pr\{h_{ab}(k_1) = h_{ab}(k_2)\} \leq 1/m$, and $\mathcal{H}_{pm}$ is universal. ∎

** Multiply-shift universal family

- Practical recommendation: the multiply-shift family parameterized by a *randomly chosen odd* multiplier:
  \[ \mathcal{H} = \{h_a : a \text{ odd},\ 1 \leq a < m,\ h_a \text{ as in the multiply-shift definition}\} \]
- *Theorem 11.5:* $\mathcal{H}$ is $2/m\text{-universal}$. (Proof omitted in the source.)
- Collision bound is twice that of a strictly universal family ($2/m$ vs. $1/m$), but compute speed in practice typically more than compensates.

** Hashing long inputs

- Inputs may be too long to encode modulo a reasonable prime or to fit in a single machine word — typical case: variable-length byte strings.

*** Number-theoretic approaches

- Extend the universal construction of §11.3.4 to variable-length inputs; details deferred to §11.5.2.

*** Cryptographic hashing

- *Cryptographic hash functions*: complex pseudorandom functions designed for cryptography, but robust, widely implemented, and usable as hash-table hash functions.
- Input: arbitrary byte string. Output: fixed-length block.
- Example: SHA-256 (NIST standard) emits 256 bits (32 bytes) for any input.
- Hardware support: AES-NI executes in tens of nanoseconds; a CBC-MAC over AES is a usable hash function.
- Cryptographic hash functions approximate a *random oracle* — equivalent to an independent uniform hash function family. The random oracle itself is a theoretical, unachievable ideal: a deterministic function returning a randomly chosen output for each input, with the same output on repeat queries.
- Concrete constructions:
  - Direct: $h(k) = \text{SHA-256}(k) \bmod m$.
  - Family via prepended "salt" $a$: $h_a(k) = \text{SHA-256}(a \mathbin\Vert k) \bmod m$, where $a \mathbin\Vert k$ denotes string concatenation.
- §11.5 covers an RC6-based design.

* 11.4 Open addressing

** Concept and operations

- *Open addressing*: all elements reside inside the hash table itself — each slot contains either an element or NIL. No external lists or pointers; the memory saved allows more slots in the same space, potentially fewer collisions and faster retrieval.
- The table can fill up → $\alpha$ can never exceed 1.
- Collision handling: an element is placed in its first-choice slot if possible, otherwise its second choice, and so on until an empty slot is found. Different elements have different preference orders.
- To search: follow the element's preference order until the key is found or an empty slot proves it absent.

- A *probe* is one examination of a slot. The hash function takes the probe number (starting from 0) as a second input:
  \[ h : U \times \{0, 1, \ldots, m-1\} \to \{0, 1, \ldots, m-1\} \]
- The *probe sequence* $\langle h(k,0), h(k,1), \ldots, h(k,m-1) \rangle$ must be a permutation of $\langle 0, 1, \ldots, m-1 \rangle$ for every key $k$, so that every slot is eventually considered.
- =HASH-INSERT= assumes keys carry no satellite data (slot stores the key itself, or NIL). It returns the slot where $k$ is stored or signals overflow.
- =HASH-SEARCH= probes the same sequence that insertion would use; it terminates successfully on a match, unsuccessfully on NIL (since $k$ would have been placed there, not later).

#+begin_example
HASH-INSERT(T, k)
1  i = 0
2  repeat
3      q = h(k, i)
4      if T[q] == NIL
5          T[q] = k
6          return q
7      else i = i + 1
8  until i == m
9  error "hash table overflow"

HASH-SEARCH(T, k)
1  i = 0
2  repeat
3      q = h(k, i)
4      if T[q] == k
5          return q
6      i = i + 1
7  until T[q] == NIL or i == m
8  return NIL
#+end_example

** Deletion

- Deletion is tricky: storing NIL in a vacated slot $q$ would break searches for any key $k$ whose insertion probed and found $q$ occupied.
- Standard fix: mark the slot with a special value DELETED instead of NIL. =HASH-INSERT= treats DELETED as empty (can insert there); =HASH-SEARCH= skips over it.
- Downside: with DELETED markers, search time no longer depends solely on $\alpha$. For this reason chaining is often preferred when deletions are frequent.
- Linear probing (§11.5.1) avoids the DELETED marker entirely.

** Independent uniform permutation hashing

- *Independent uniform permutation hashing* (also confusingly called *uniform hashing* in the literature): the probe sequence for each key $k$ is equally likely to be any of the $m!$ permutations of $\langle 0, 1, \ldots, m-1 \rangle$.
- Generalizes independent uniform hashing (which produces a single slot) to producing an entire probe sequence.
- Not implementable directly; double hashing and linear probing are practical approximations.

** Double hashing

- *Double hashing*: $h(k, i) = (h_1(k) + i \cdot h_2(k)) \bmod m$, where $h_1$ and $h_2$ are *auxiliary hash functions*.
- First probe goes to $T[h_1(k)]$; successive probes are offset by $h_2(k) \bmod m$.
- The probe sequence depends on $k$ in *two* ways (initial position $h_1(k)$ and step size $h_2(k)$).
- $h_2(k)$ must be relatively prime to $m$ for the full table to be searched. Two convenient designs:
  - $m = 2^\ell$: make $h_2$ always return an odd number.
  - $m$ prime: let $h_2$ always return a positive integer less than $m$.
- Example with $m$ prime: $h_1(k) = k \bmod m$, $h_2(k) = 1 + (k \bmod m')$ with $m' < m$ (say, $m' = m - 1$). For $k = 123456$, $m = 701$, $m' = 700$: $h_1(k) = 80$, $h_2(k) = 257$.
- When $m$ is prime or an exact power of 2, double hashing produces $\Theta(m^2)$ probe sequences (one per $(h_1(k), h_2(k))$ pair) — far from $m!$ but large enough for good practical performance.

[FIGURE 11.5: double hashing insertion with $m = 13$, $h_1(k) = k \bmod 13$, $h_2(k) = 1 + (k \bmod 11)$; key 14 goes to slot 9 after slots 1 and 5 are found occupied]

** Linear probing

- *Linear probing*: set $h_2(k) = 1$ for all $k$, giving
  \[ h(k, i) = (h_1(k) + i) \bmod m \]
- Simplest open-addressing scheme. First probe at $h_1(k)$; if occupied, try $h_1(k)+1, h_1(k)+2, \ldots$, wrapping around to 0 after slot $m-1$, stopping before revisiting $h_1(k)$.
- Only $m$ distinct probe sequences (one per starting slot) — very far from $m!$.
- Revisited in §11.5.1.

** Analysis of open-address hashing

- Load factor: $\alpha = n/m$. With open addressing $n \leq m$, so $\alpha \leq 1$. The analysis requires $\alpha < 1$ (at least one empty slot) and assumes no deletions.
- Assume *independent uniform permutation hashing*.
- Intuition for the bound $1/(1-\alpha) = 1 + \alpha + \alpha^2 + \alpha^3 + \cdots$: the first probe always occurs; with probability $\approx \alpha$ the first slot is occupied, triggering a second probe; with probability $\approx \alpha^2$ both are occupied, triggering a third; and so on.

*** Theorem 11.6 — unsuccessful search

- *Theorem 11.6:* given an open-address hash table with $\alpha = n/m < 1$, the expected number of probes in an unsuccessful search is at most $1/(1 - \alpha)$, assuming independent uniform permutation hashing and no deletions.
- *Proof.*
  - Let $X$ be the number of probes. Every probe but the last hits an occupied slot; the last hits an empty slot.
  - Define $A_i$ ($i = 1, 2, \ldots$) = event that the $i$th probe occurs and finds an occupied slot. Then $\{X \geq i\} = A_1 \cap A_2 \cap \cdots \cap A_{i-1}$.
  - By the chain rule for conditional probability:
    \[ \Pr\{A_1 \cap \cdots \cap A_{i-1}\} = \Pr\{A_1\} \cdot \Pr\{A_2 \mid A_1\} \cdots \Pr\{A_{i-1} \mid A_1 \cap \cdots \cap A_{i-2}\} \]
  - $\Pr\{A_1\} = n/m$. For $j > 1$, the $j$th probe lands on one of $m - (j-1)$ unexamined slots, of which $n - (j-1)$ are occupied (by independence of the permutation), giving $\Pr\{A_j \mid A_1 \cap \cdots \cap A_{j-1}\} = (n-j+1)/(m-j+1)$.
  - Since $n < m$ implies $(n-j)/(m-j) \leq n/m$ for $0 \leq j < m$:
    \[ \Pr\{X \geq i\} = \frac{n}{m} \cdot \frac{n-1}{m-1} \cdots \frac{n-i+2}{m-i+2} \leq \left(\frac{n}{m}\right)^{i-1} = \alpha^{i-1} \]
    (the product has $i-1$ factors; when $i = 1$ the product is empty = 1, so $\Pr\{X \geq 1\} = 1$).
  - For $i > n+1$ all $n$ occupied slots have been probed, so the next probe is empty: $\Pr\{X \geq i\} = 0$.
  - Bound $\mathrm{E}[X]$ using equation (C.28):
    \[ \mathrm{E}[X] = \sum_{i=1}^{\infty} \Pr\{X \geq i\} = \sum_{i=1}^{n+1} \Pr\{X \geq i\} \leq \sum_{i=1}^{\infty} \alpha^{i-1} = \sum_{i=0}^{\infty} \alpha^i = \frac{1}{1 - \alpha} \]
    (geometric series, $0 \leq \alpha < 1$, by equation (A.7)). ∎

- *Interpretation.* If $\alpha$ is a constant, unsuccessful search is $O(1)$. At half full: $\leq 1/(1 - 0.5) = 2$ probes. At 90% full: $\leq 1/(1 - 0.9) = 10$.

*** Corollary 11.7 — insertion

- *Corollary 11.7:* inserting into an open-address table with $\alpha < 1$ takes at most $1/(1-\alpha)$ probes on average, assuming independent uniform permutation hashing and no deletions.
- *Proof.* Insertion requires an unsuccessful search (to find the first empty slot) followed by placing the key. Hence the bound is the same as Theorem 11.6. ∎

*** Theorem 11.8 — successful search

- *Theorem 11.8:* given an open-address hash table with $\alpha < 1$, the expected number of probes in a successful search is at most $\frac{1}{\alpha} \ln \frac{1}{1 - \alpha}$, assuming independent uniform permutation hashing, no deletions, and each stored key equally likely to be searched.
- *Proof.*
  - Searching for key $k$ replays the probe sequence from when $k$ was inserted. If $k$ was the $(i+1)$st key inserted, the load factor at insertion time was $i/m$, so by Corollary 11.7 the expected probes for that insertion (and hence for searching $k$) are at most $\frac{1}{1 - i/m} = \frac{m}{m - i}$.
  - Average over all $n$ keys:
    \[ \frac{1}{n} \sum_{i=0}^{n-1} \frac{m}{m-i} = \frac{m}{n} \sum_{i=0}^{n-1} \frac{1}{m-i} = \frac{1}{\alpha} \sum_{k=m-n+1}^{m} \frac{1}{k} \]
  - Bounding the sum by an integral (inequality (A.19)):
    \[ \leq \frac{1}{\alpha} \int_{m-n}^{m} \frac{1}{x}\, dx = \frac{1}{\alpha}(\ln m - \ln(m-n)) = \frac{1}{\alpha} \ln \frac{m}{m-n} = \frac{1}{\alpha} \ln \frac{1}{1-\alpha} \tag*{$\blacksquare$} \]

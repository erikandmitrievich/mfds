* Problem 81 :dynamic_programming:greedy:rod_cutting:
** Task
#+begin_quote
Show, by means of a counterexample, that the following “greedy” strategy does not always determine an optimal way to cut rods.

Define the density of a rod of length $i$ to be $p_i/i$, that is, its value per inch. The greedy strategy for a rod of length $n$ cuts off a first piece of length $i$, where $1 \leq i \leq n$, having maximum density. It then continues by applying the greedy strategy to the remaining piece of length $n - i$.
#+end_quote

** Solution

#+begin_src  julia :results output
using Test

p = [2, 4, 6, 8, 10, 20, 17, 20, 24, 30]

function cut_rod(p, n)
    n == 0 && return 0
    q = 0
    for i in 1:n
        q = max(q, p[i] + cut_rod(p, n - i))
    end
    q
end

function greedy_cut(p, n)
    total = 0
    while n > 0
        best_i, best_d = 0, -Inf
        for i in 1:n
            d = p[i] / i
            if d > best_d
                best_d, best_i = d, i
            end
        end
        total += p[best_i]
        n -= best_i
    end
    total
end


@testset "rod cutting" begin
    @testset "cut_rod base + small cases" begin
        @test cut_rod(p, 0) == 0
        @test cut_rod(p, 1) == 2
        @test cut_rod(p, 2) == 4
        @test cut_rod(p, 6) == 20
        @test cut_rod(p, 10) == 30
    end

    @testset "greedy matches optimum on easy cases" begin
        for n in 0:6
            @test greedy_cut(p, n) == cut_rod(p, n)
        end
    end

    @testset "greedy fails at n = 10 (counterexample)" begin
        @test cut_rod(p, 10) == 30
        @test greedy_cut(p, 10) == 28
        @test greedy_cut(p, 10) < cut_rod(p, 10)
    end
end

* Problem 82 :dynamic_programming:rod_cutting:
** Task
#+begin_quote
Consider a modification of the rod-cutting problem in which, in addition to a price $p_i$ for each rod, each cut incurs a fixed cost of $c$. The revenue associated with a solution is now the sum of the prices of the pieces minus the costs of making the cuts. Give a dynamic-programming algorithm to solve this modified problem.
#+end_quote

** Solution

#+begin_src julia :results output
using Test

function bottom_up_cut_rod_cstm(p, n, c)
    r = Vector{Int}(undef, n + 1)
    r[1] = 0
    for j in 1:n
        q = p[j]
        for i in 1:j-1
            q = max(q, p[i] + r[j - i + 1] - c)
        end
        r[j + 1] = q
    end
    r[n + 1]
end


p = [1, 5, 8, 9, 10, 17, 17, 20, 24, 30]

@testset "cut_rod_cost" begin
    opt = [0, 1, 5, 8, 10, 13, 17, 18, 22, 25, 30]

    # no cost
    for n in 0:10
        @test bottom_up_cut_rod_cstm(p, n, 0) == opt[n + 1]
    end

    # expensive cost
    for n in 1:10
        @test bottom_up_cut_rod_cstm(p, n, 10) == p[n]
    end

    @test bottom_up_cut_rod_cstm(p, 4, 1) == 9    # uncut
    @test bottom_up_cut_rod_cstm(p, 5, 1) == 12   # 2+3: 5+8-1
end

* Problem 83 :dynamic_programming:matrix_chain:complexity:
** Task
#+begin_quote
Let $R(i, j)$ be the number of times that table entry $m[i, j]$ is referenced while computing other table entries in a call of MATRIX-CHAIN-ORDER. Show that the total number of references for the entire table is

$$\sum_{i=1}^{n} \sum_{j=i}^{n} R(i, j) = \frac{n^3 - n}{3}$$
#+end_quote

** Solution

MATRIX-CHAIN-ORDER computes $m[i,j]$ for $i < j$ via

$$m[i,j] = \min_{i \le k < j}\{m[i,k] + m[k+1,j] + p_{i-1}p_k p_j\}.$$

For each such $(i,j)$ the inner loop runs over $k = i, \ldots, j-1$ and makes exactly two table references per iteration: $m[i,k]$ and $m[k+1,j]$. So computing $m[i,j]$ contributes $2(j-i)$ references. Entries with $i = j$ are base cases and reference nothing.

Total references:

$$T(n) = \sum_{i=1}^{n}\sum_{j=i+1}^{n} 2(j-i).$$

Substitute $l = j - i$, $l = 1, \ldots, n-i$:

$$T(n) = 2\sum_{i=1}^{n}\sum_{l=1}^{n-i} l = 2\sum_{i=1}^{n}\frac{(n-i)(n-i+1)}{2} = \sum_{r=0}^{n-1} r(r+1),$$

where $r = n - i$. Using $\sum_{r=0}^{n-1} r^2 = \frac{(n-1)n(2n-1)}{6}$ and $\sum_{r=0}^{n-1} r = \frac{(n-1)n}{2}$:

\begin{align*}
T(n) &= \frac{(n-1)n(2n-1)}{6} + \frac{(n-1)n}{2} \\
&= \frac{(n-1)n(2n-1) + 3(n-1)n}{6} \\
&= \frac{(n-1)n(2n+2)}{6} \\
&= \frac{n(n-1)(n+1)}{3} \\
&= \frac{n^3 - n}{3}
\end{align*}

#+begin_src julia :results output
function matrix_chain_order(p, n)
    m = zeros(Int, n, n)
    s = zeros(Int, n, n)
    c = 0

    for i in 1:n
        m[i, i] = 0
    end

    for l in 2:n
        for i in 1:(n - l + 1)
            j = i + l - 1
            m[i, j] = typemax(Int)
            for k in i:(j-1)
                q = m[i, k] + m[k+1, j] + p[i] * p[k+1] * p[j+1]
                if q < m[i, j]
                    m[i, j] = q
                    s[i, j] = k
                end
                c += 2
            end
        end
    end
    return (m, s, c)
end

* Problem 84 :dynamic_programming:greedy:matrix_chain:
** Task
#+begin_quote
As stated, in dynamic programming, you first solve the subproblems and then choose which of them to use in an optimal solution to the problem.

Professor Capulet claims that she does not always need to solve all the subproblems in order to find an optimal solution. She suggests that she can find an optimal solution to the matrix-chain multiplication problem by always choosing the matrix $A_k$ at which to split the subproduct $A_i A_{i+1} \cdots A_j$ (by selecting $k$ to minimize the quantity $p_{i-1} p_k p_j$) before solving the subproblems. Find an instance of the matrix-chain multiplication problem for which this greedy approach yields a suboptimal solution.
#+end_quote

** Solution

#+begin_src julia :results output
using Test

function matrix_chain_order(p, n)
    m = zeros(Int, n, n)
    s = zeros(Int, n, n)
    c = 0

    for i in 1:n
        m[i, i] = 0
    end

    for l in 2:n
        for i in 1:(n - l + 1)
            j = i + l - 1
            m[i, j] = typemax(Int)
            for k in i:(j-1)
                q = m[i, k] + m[k+1, j] + p[i] * p[k+1] * p[j+1]
                if q < m[i, j]
                    m[i, j] = q
                    s[i, j] = k
                end
                c += 2
            end
        end
    end
    return (m, s, c)
end

# for recursion
function greedy_chain(p, i, j)
    # base case: a single matrix needs 0 multiplications
    if i == j
        return 0
    end

    best_k = i
    min_split_cost = typemax(Int)

    for k in i:(j-1)
        cost = p[i] * p[k+1] * p[j+1]
        if cost < min_split_cost
            min_split_cost = cost
            best_k = k
        end
    end

    # recursively solve the left and right subproblems
    left_cost = greedy_chain(p, i, best_k)
    right_cost = greedy_chain(p, best_k + 1, j)

    # total cost is the cost of the subproblems plus the split we chose
    return left_cost + right_cost + min_split_cost
end

# wrapper
function up_bottom_matrix_chain_order(p, n)
    return greedy_chain(p, 1, n)
end

@testset "comparing bottom-up and up-bottom" begin

    @testset "suboptimal greedy choice" begin
        p = [1, 2, 100, 10]
        n = length(p) - 1

        m, s, c = matrix_chain_order(p, n)
        dp_cost = m[1, n]

        greedy_cost = up_bottom_matrix_chain_order(p, n)

        println("DP Optimal Cost: $dp_cost")
        println("Greedy Cost:     $greedy_cost")
        @test greedy_cost > dp_cost
    end

end

* Problem 85 :dynamic_programming:rod_cutting:optimal_substructure:
** Task
#+begin_quote
Suppose that the rod-cutting problem of Section 14.1 also had a limit $l_i$ on the number of pieces of length $i$ allowed to be produced, for $i = 1, 2, \ldots, n$. Show that the optimal-substructure property described in Section 14.1 no longer holds.
#+end_quote

** Solution

|--------+----+----+----+----+---|
| length |  1 |  2 |  3 |  4 | 5 |
|--------+----+----+----+----+---|
| cost   |  1 |  2 |  3 |  4 | 7 |
|--------+----+----+----+----+---|
| limit  | 10 | 10 | 10 | 10 | 1 |
|--------+----+----+----+----+---|

Take $n = 10$. Independently, $r_5 = 7$ (one length-5 piece). The recursion would give $r_{10} \ge p_5 + r_5 = 14$ via $10 = 5+5$, but this uses two length-5 pieces and violates $l_5 = 1$.

True optimum: $12$ — one length-5 piece (7) plus a length-5 remainder restricted to lengths $\le 4$ (value 5).

The optimum on length 10 does not contain the optimum on length 5. State indexed by remaining length alone is insufficient; limits must be carried in the state.

* Problem 86 :dynamic_programming:graph:dag:longest_path:
** Task
#+begin_quote
Longest simple path in a directed acyclic graph: A directed graph $\Gamma$ is a graph, where every edge has a direction. Mathematically, that means that $\Gamma = (V, E)$, with a finite set $V$ of vertices and a finite set $E \subseteq V \times V$ of directed edges. Note that edges of directed graphs are ordered pairs, so $(i, j) \neq (j, i)$ if $i \neq j$. A path of length $k$ in a directed graph is a sequence of vertices $v_0 v_1 v_2 \ldots v_k$, where $(v_{i-1}, v_i) \in E$ for all $i = 1, \ldots, k$. A path is called a cycle, if $v_0 = v_k$. A directed graph without cycles is called a directed acyclic graph, short DAG.

You are given a directed acyclic graph $\Gamma = (V, E)$ with real-valued edge weights, i.e., every edge $e \in E$ has a weight $w_e \in \mathbb{R}$, and two distinguished vertices $s$ and $t$. The weight of a path is the sum of the weights of the edges in the path. Describe a dynamic-programmingr approach for finding a longest weighted simple path from $s$ to $t$. What is the running time of your algorithm?
#+end_quote

** Solution

DAG $\rightarrow$ every path is simple (a repeat would close a cycle), so this is just longest path. Let $\mathrm{dist}(v)$ be the max weight of an $s$–$v$ path, $-\infty$ if none:

$$\mathrm{dist}(s) = 0, \qquad \mathrm{dist}(v) = \max_{(u,v)\in E}\{\mathrm{dist}(u) + w(u,v)\}.$$

In topological order every predecessor of $v$ is final before $v$, so one relaxation pass suffices (DAG-SHORTEST-PATHS with $\max$ for $\min$).

Answer $\mathrm{dist}(t)$; store predecessors to recover the path. Time $\Theta(V + E)$.

* Problem 87 :dynamic_programming:string:subsequence:palindrome:
** Task
#+begin_quote
Longest palindrome subsequence: A palindrome is a nonempty string over some alphabet that reads the same forward and backward. Examples of palindromes are all strings of length 1, civic, racecar, and aibohphobia (fear of palindromes).

Give an efficient algorithm to find the longest palindrome that is a subsequence of a given input string. For example, given the input character, your algorithm should return carac. What is the running time of your algorithm?
#+end_quote

** Solution

Running time: $\Theta(n^2)$, space $\Theta(n^2)$, where $n = |s|$.

Reduction is $\Theta(n)$ (reversing the string); LCS on two length-$n$ strings is $\Theta(n^2)$ via the table fill; reconstruction is $\Theta(n)$. Total $\Theta(n^2)$.

#+begin_src julia :results output
using Test

function is_palindrome(s::AbstractString)
    i, j = firstindex(s), lastindex(s)
    while i < j
        (s[i] == s[j]) || (return false)
        i, j = nextind(s, i), prevind(s, j)
    end
    true
end

function lcs_length(X, Y)
    m, n = length(X), length(Y)
    c = zeros(Int, m+1, n+1)
    b = Matrix{Char}(undef, m, n)
    for i in 1:m, j in 1:n
        if X[i] == Y[j]
            c[i+1, j+1] = c[i, j] + 1
            b[i, j] = '↖'
        elseif c[i, j+1] ≥ c[i+1, j]
            c[i+1, j+1] = c[i, j+1]
            b[i, j] = '↑'
        else
            c[i+1, j+1] = c[i+1, j]
            b[i, j] = '←'
        end
    end
    c, b
end

function lcs_string(b, X, i=size(b,1), j=size(b,2))
    chars = Char[]
    while i > 0 && j > 0
        if b[i, j] == '↖'
            push!(chars, X[i])
            i -= 1; j -= 1
        elseif b[i, j] == '↑'
            i -= 1
        else
            j -= 1
        end
    end
    String(reverse!(chars))
end

function lps(s::AbstractString)
    c, b = lcs_length(s, reverse(s))
    return lcs_string(b, s)
end

@testset "longest palindrome" begin
    @testset "is_palindrome" begin
        for s in ("civic", "racecar", "abccba");  @test  is_palindrome(s); end
        for s in ("apple", "banana", "pinapple"); @test !is_palindrome(s); end
    end
end

@testset "longest palindrome subsequence" begin
    function is_subseq(sub, s)
        it = Iterators.Stateful(s)
        all(c -> any(==(c), it), sub)
    end

    cases = [
        ("",          0),
        ("a",         1),
        ("ab",        1),
        ("aaaa",      4),
        ("abcd",      1),
        ("racecar",   7),
        ("abcba",     5),
        ("bbbab",     4),
        ("cbbd",      2),
        ("character", 5),
        ("agbdba",    5),
    ]

    for (s, len) in cases
        r = lps(s)
        @test length(r) == len
        @test is_palindrome(r)
        @test is_subseq(r, s)
    end
end

* Problem 88 :dynamic_programming:optimization:inventory:
** Task
#+begin_quote
The Rinky Dink Company makes machines that resurface ice rinks. The demand for such products varies from month to month, and so the company needs to develop a strategy to plan its manufacturing given the fluctuating, but predictable, demand.

The company wishes to design a plan for the next $n$ months. For each month $i$, the company knows the demand $d_i$, that is, the number of machines that it will sell. Let $D = \sum_{i=1}^{n} d_i$ be the total demand over the next $n$ months. The company keeps a full-time staff who provide labor to manufacture up to $m$ machines per month. If the company needs to make more than $m$ machines in a given month, it can hire additional, part-time labor, at a cost that works out to $c$ dollars per machine. Furthermore, if the company is holding any unsold machines at the end of a month, it must pay inventory costs. The company can hold up to $D$ machines, with the cost for holding $j$ machines given as a function $h(j)$ for $j = 1, 2, \ldots, D$ that monotonically increases with $j$.

Give an algorithm that calculates a plan for the company that minimizes its costs while fulfilling all the demand. The running time should be polynomial in $n$ and $D$.
#+end_quote

** Solution

No backlogging; state = end-of-month inventory $s_i \in \{0,\dots,D\}$, $s_0 = 0$, $D = \sum_i d_i$. Month $i$ makes $x_i = s_i - s_{i-1} + d_i \ge 0$, paying overtime $\kappa(x) = c\max(0, x - m)$ and holding $h(s_i)$, $h(0) = 0$.

$$C(i, j) = h(j) + \min_{0 \le j' \le j + d_i}\{C(i-1, j') + \kappa(j + d_i - j')\}, \quad C(0,0) = 0,\ C(0, j{>}0) = \infty.$$

$h$ increasing $\implies$ optimum ends $s_n = 0$, so the answer is $C(n, 0)$; the minimizing $j'$ recovers each $x_i$. Time $O(nD^2)$ - pseudo-polynomial ($D$ is exponential in input size, as with knapsack).

* Problem 89 :dynamic_programming:string:optimal_partition:
** Task
#+begin_quote
A certain string-processing programming language allows you to break a string into two pieces. Because this operation copies the string, it costs $n$ time units to break a string of $n$ characters into two pieces.

Suppose that you want to break a string into many pieces. The order in which the breaks occur can affect the total amount of time used. For example, suppose that you want to break a 20-character string after characters 2, 8, and 10 (numbering the characters in ascending order from the left-hand end, starting from 1).

If you program the breaks to occur in left-to-right order, then the first break costs 20 time units, the second break costs 18 time units (breaking the string from characters 3 to 20 at character 8), and the third break costs 12 time units, totaling 50 time units.

If you program the breaks to occur in right-to-left order, however, then the first break costs 20 time units, the second break costs 10 time units, and the third break costs 8 time units, totaling 38 time units.

In yet another order, you could break first at 8 (costing 20), then break the left piece at 2 (costing another i8), and finally the right piece at 10 (costing 12), for a total cost of 40.

Design an algorithm that, given the numbers of characters after which to break, determines a least-cost way to sequence those breaks. More formally, given an array $L[1 : m]$ containing the break points for a string of $n$ characters, compute the lowest cost for a sequence of breaks, along with a sequence of breaks that achieves this cost.
#+end_quote

** Solution

#+begin_src julia :results output
using Test

function min_cost_string_break(n, bp)
    positions = [0; sort(bp); n]
    p = length(positions)
    cost = zeros(Int, p, p)
    split = zeros(Int, p, p)
    for len in 3:p
        for i in 1:p-len+1
            j = i + len - 1
            best, best_k = typemax(Int), 0
            for k in i+1:j-1
                c = cost[i,k] + cost[k,j]
                if c < best
                    best, best_k = c, k
                end
            end
            cost[i,j] = best + positions[j] - positions[i]
            split[i,j] = best_k
        end
    end

    sequence = Int[]
    function emit(i, j)
        j - i < 2 && return
        k = split[i,j]
        push!(sequence, positions[k])
        emit(i, k)
        emit(k, j)
    end
    emit(1, p)

    return cost[1, p], sequence
end

@testset "min_cost_string_break" begin
    @test min_cost_string_break(20, [2, 8, 10]) == (38, [10, 2, 8])
    @test min_cost_string_break(20, [10, 2, 8]) == (38, [10, 2, 8])
    @test min_cost_string_break(4,  [1, 2])     == (6,  [2, 1])
    @test min_cost_string_break(10, Int[])      == (0,  Int[])
    @test min_cost_string_break(15, [4])        == (15, [4])
    @test min_cost_string_break(10, [2, 5, 8])  == (20, [5, 2, 8])
end

*** Master theorem (Theorem 4.1)
:PROPERTIES:
:LECTURE_REF: lec_04
:CUSTOM_ID: lec04-a-master-theorem
:END:
Signal: "this is one of the theorems that might be for the exam"
Let $a > 0$ and $b > 1$ be constants and $f(n)$ the driving function, with
$$T(n) = a\, T(n/b) + f(n)$$
(or the floor/ceiling form $T(n) = a' T(\lfloor n/b \rfloor) + a'' T(\lceil n/b \rceil) + f(n)$, $a' + a'' = a$). The watershed function is $n^{\log_b a}$. Then [reconstructed; ASR garbled, matches CLRS 4th-ed canonical form]:
1. If $f(n) = O(n^{\log_b a - \epsilon})$ for some $\epsilon > 0$, then $T(n) = \Theta(n^{\log_b a})$. [reconstructed]
2. If $f(n) = \Theta(n^{\log_b a} \lg^k n)$ for some $k \ge 0$, then $T(n) = \Theta(n^{\log_b a} \lg^{k+1} n)$. [reconstructed]
3. If $f(n) = \Omega(n^{\log_b a + \epsilon})$ for some $\epsilon > 0$ and the regularity condition $a\, f(n/b) \le c\, f(n)$ holds for some constant $0 < c < 1$ and all large $n$, then $T(n) = \Theta(f(n))$. [reconstructed]

** B. Implicit emphasis (inferred)
*** RANDOMIZE-IN-PLACE: loop invariant, correctness proof, and running time
:PROPERTIES:
:LECTURE_REF: lec_10
:CUSTOM_ID: lec10-b-randomize-in-place
:END:
Signal: "Remember that because this is an important algorithm"

Loop invariant [reconstructed]: prior to iteration $i$, the subarray $A[1..i-1]$ contains an $(i-1)$ permutation drawn from $A$, and every such $(i-1)$ permutation appears with probability
$$\frac{(n-i+1)!}{n!}.$$

Maintenance [reconstructed]: let $E_1$ = "$A[1..i-1]$ holds a fixed $(i-1)$ permutation $\langle x_1,\ldots,x_{i-1}\rangle$"; let $E_2$ = "$x_i$ is chosen for $A[i]$ in iteration $i$." Since $E_1$ and $E_2$ are not independent:
\begin{align*}
\Pr[E_1 \cap E_2] &= \Pr[E_2 \mid E_1]\cdot\Pr[E_1] \\
                  &= \frac{1}{n-i+1}\cdot\frac{(n-i+1)!}{n!} \\
                  &= \frac{(n-i)!}{n!},
\end{align*}
which equals $\frac{(n-(i+1)+1)!}{n!}$, confirming the invariant for iteration $i+1$.

Termination: at loop end $i = n+1$, so every permutation appears with probability $\frac{0!}{n!} = \frac{1}{n!}$.

Running time: $O(n)$ (one pass; one random draw and one swap per step).

*** BUILD-MAX-HEAP runs in O(n), not O(n lg n)
:PROPERTIES:
:LECTURE_REF: lec_10
:CUSTOM_ID: lec10-b-build-heap-on
:END:
Signal: "definitely looks like it'd be n log n. And the point is, it isn't."

Tool used in proof: MAX-HEAPIFY called at a node of height $h$ costs $O(h)$, i.e., $T(v) = O(h(v))$.

Cost bound [reconstructed]:
$$T(n) \le \sum_{h=0}^{\lfloor \lg n \rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil \cdot O(h) \le cn\sum_{h=0}^{\lfloor \lg n \rfloor} \frac{h}{2^h}.$$

Key identity (differentiate the geometric series $f(x) = \frac{1}{1-x/2}$ and evaluate at $x = 1$) [reconstructed]:
$$\sum_{h=0}^{\infty}\frac{h}{2^h} = f'(1) = \frac{1/2}{(1/2)^{2}} = 2.$$

Therefore $T(n) = O(n)$.

*** Comparison-sort worst-case lower bound $\Omega(n \lg n)$
:PROPERTIES:
:LECTURE_REF: lec_12
:CUSTOM_ID: lec12-b-comparison-sort-lower-bound
:END:
Signal: "you still should know that you cannot sort things faster than $n \lg n$"

*** Double-color device (red-black / black-black)
:PROPERTIES:
:LECTURE_REF: lec_19
:CUSTOM_ID: lec19-b-double-color-device
:END:
Signal: "we replace violating five with violating one, so we introduce new colors."
Transcribed semantics:

- A *red-black* node is red in the tree but counts as $1$ black when traversed.

*** RB-DELETE-FIXUP four-case structure
:PROPERTIES:
:LECTURE_REF: lec_19
:CUSTOM_ID: lec19-b-fixup-four-cases
:END:
Signal: "case one is the sibling is red and the other cases the sibling is black."
Transcribed case map (stated for $x$ = left child; right-child branch is the mirror image, see C):
- Case 1: sibling $w$ red $\rightarrow$ rotate + recolor to *reduce* to case 2/3/4 (does not terminate).
- Case 2: $w$ black, both children of $w$ black $\rightarrow$ recolor, push the extra black up to the parent, continue from there.
- Case 3: $w$ black, near child red / far child black $\rightarrow$ rotate to *reduce* to case 4.
- Case 4: $w$ black, far child red $\rightarrow$ rotate + recolor, *terminates*; extra black is discharged, loop ends (new problem node at most the root).

- y-original-color = the color removed from the tree; fixup runs only if it was black (line 21).

*** Optimal substructure of rod cutting
:PROPERTIES:
:LECTURE_REF: lec_20
:CUSTOM_ID: lec20-b-optimal-substructure
:END:
Signal: "a problem that has these properties called subproblem optimal."
(Professor's term "subproblem optimal" = CLRS "optimal substructure"; phrasing variance only, not flagged as a deviation.) An optimal cut of length $n$ contains optimal cuts of its sub-pieces, so only optimal subproblem values matter. Central recurrence (with $c_k$ = price of a piece of length $k$):
$$r_n = \max_{1 \le k \le n}\bigl(c_k + r_{n-k}\bigr), \qquad r_0 = 0.$$

*** Overlapping subproblems (the DP insight)
:PROPERTIES:
:LECTURE_REF: lec_20
:CUSTOM_ID: lec20-b-overlapping-subproblems
:END:
Signal: "we have done a lot of computations many times in a row."
The naive recursive CUT-ROD recomputes the same subproblems repeatedly (the recursion tree enumerates every cut), so it is still $\Theta(2^{n})$. The fix is to remember already-computed subproblem results; for length $n$ only the values $r_0,\dots,r_{n}$ are ever needed.

*** Memoized (top-down) and bottom-up both run in $\Theta(n^2)$
:PROPERTIES:
:LECTURE_REF: lec_20
:CUSTOM_ID: lec20-b-memoization-bottomup-nsquared
:END:
Signal: "it's quadratic if you do it better but it's exponential if you do it bad."
Top-down memoization initializes $R[0..n]$ to $-\infty$ (sentinel for "not yet computed", valid since prices are non-negative) and returns a stored value if present. Bottom-up fills $R$ for lengths $1$ to $n$ with a nested loop. Both visit $\sum_{k=0}^{n} k = \tfrac{n(n-1)}{2}$ subproblem-work units $\Rightarrow \Theta(n^2)$, versus $\Theta(2^n)$ for naive recursion.

*** Brute-force enumeration is exponential
:PROPERTIES:
:LECTURE_REF: lec_20
:CUSTOM_ID: lec20-b-bruteforce-exponential
:END:
Signal: "you will never, ever, ever finish that stuff if you have length 50."
A rod of length $L$ has $L-1$ cut positions, each cut-or-not, giving $2^{L-1}$ ways to cut (e.g. $L=10 \Rightarrow 2^9 = 512$). Heavily emphasized as intractable.

*** Reconstructing the actual cuts, not just the optimal value
:PROPERTIES:
:LECTURE_REF: lec_20
:CUSTOM_ID: lec20-b-reconstruct-solution
:END:
Signal: "I forgot an important thing actually before we go there."
The value function returns only the optimal revenue, not where to cut. Store the first-cut length in an auxiliary array $s[1..n]$ (update $s[j] = k$ whenever a larger candidate $p = c_k + r_{j-k}$ is found). Recover the cuts:

*** Optimization problem formulation
:PROPERTIES:
:LECTURE_REF: lec_20
:CUSTOM_ID: lec20-b-optimization-formulation
:END:
Signal: "a very, very important part of data science, which is optimization."
Standard form: objective $f$, variables (controllable) vs constants (fixed), and constraints, written
